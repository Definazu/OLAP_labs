## Запуск в Arch Linux под WSL2

Из PowerShell откройте терминал с доступом к Docker командой `wsl.exe -d Arch -u root --cd /mnt/d/Projects/OLAP/project`. При запуске из архива перейдите в папку, куда его распаковали. На свежем Arch запустите Docker через `systemctl start docker`.

1. `docker compose up -d`
2. `python -m venv .venv && .venv/bin/python -m pip install -r requirements.txt`
3. `.venv/bin/python etl/load.py`
4. `.venv/bin/python dashboards/setup.py`
5. `.venv/bin/python etl/verify.py`

На уже настроенной машине зависимости установлены в `/home/definazu/.local/share/olap-course/venv`, поэтому можно использовать этот Python для шагов 3–5. `etl/load.py` создаёт `.run/retail.duckdb`. С `--duckdb-only` он выполняет локальный этап без Docker. `dashboards/setup.py` выводит URL дашборда, а при первом запуске записывает логин и сгенерированный пароль учебного администратора в `.run/metabase-login.json`. Этот файл используется при повторном запуске и хранится локально.

| Сервис | Порт |
|---|---|
| ClickHouse HTTP | `127.0.0.1:8123` |
| ClickHouse native | `127.0.0.1:9000` |
| Metabase | `127.0.0.1:3000` |

Если сервисы не поднялись, проверьте `docker compose ps`, `docker compose logs --tail=100` и `curl -fsS http://127.0.0.1:8123/ping`. Оставьте терминал Arch открытым на время запуска и демонстрации. Если WSL остановлен, снова откройте терминал Arch в папке проекта и выполните `docker compose up -d`. Metabase может загружаться несколько минут при первом старте. Для пробного запуска через Docker нужны образы из `compose.yaml`. В этой установке исходящий маршрут WSL2 вызывал сетевые тайм-ауты. Официальные образы и пакет DuckDB были загружены через работающий интерфейс без изменения маршрутов.

Он проверяет данные до публикации, сравнивает количества строк и эталонный оборот, затем меняет таблицы местами и удаляет старый снимок. При нарушении качества публикация останавливается. Агрегат перестраивается из нового факта при каждом полном обновлении.

## Устный путь данных

Пять CSV описывают позиции продаж, три измерения и учебную смену категории товара. ELT загружает сырьё во временные таблицы DuckDB и проверяет обязательные поля, диапазоны, дубли и ссылки. Измерения формируются до факта. Одна строка `fact_sales` — одна товарная позиция, а версия категории определяется датой продажи. Те же проверенные строки попадают в ClickHouse. Факт разбит по месяцам, а `date_id` стоит первым в ключе сортировки для запросов по периоду. Эталон суммирует `amount` из детального факта. Metabase показывает тот же итог, применяя согласованный фильтр региона. График по месяцам читает сводку «день × магазин», сверенную с фактом.
