# ClickHouse и агрегат

В `fact_sales` выбран `ORDER BY (date_id, store_id, product_sk)`. Вопросы чаще начинаются с периода, где `date_id` ограничивает диапазон разреженного индекса. Внутри даты строки сгруппированы по магазину и далее по версии товара. Ключ сортировки сам по себе допускает одинаковые значения, а дубли позиций проверяются в ELT по `sale_id`.

`PARTITION BY intDiv(date_id, 100)` группирует строки по `YYYYMM`. Это удобно для контроля или замены полного месяца, а явный фильтр по этому выражению демонстрирует отсечение частей в `EXPLAIN indexes = 1`. Запрос с одним `store_id` оставляет части всех месяцев. Пример есть в `sql/primary_index_clickhouse.sql`. В аналитике на небольшом учебном объёме сравниваем планы и совпадение ответов, поэтому время выполнения не выдаёт обобщаемой оценки выигрыша.

`agg_daily_store` хранит `SUM(amount)` для наблюдаемой пары день × магазин. Metabase сворачивает итог по дням до месяца. ELT каждый раз строит новую таблицу `agg_daily_store` из нового факта, проверяет контрольные значения и публикует её с таблицами витрины. Сверка сравнивает итог на каждой паре день × магазин. Эталонный оборот считается из детальных позиций.
